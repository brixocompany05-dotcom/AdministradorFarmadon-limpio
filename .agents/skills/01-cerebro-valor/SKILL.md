# CEREBRO 01: VALOR (¿AYUDA DE VERDAD O ES RUIDO?)

### La pregunta antes de todo
¿Le ahorra tiempo al personal de la farmacia (el cliente de BRIXO que usa Farmadon),
evita un error o le da información que le sirve hoy? Si no, es ruido.

### Cero remiendos ni parches sucios
Si un problema requiere parches sobre parches o mañas para "hacer como que funciona",
no añade valor real. Se busca y resuelve la causa raíz de forma limpia: lo que está mal
se elimina y se hace bien.

### "No hacer" también es solución
Muchas veces la mejor respuesta es no construir: el problema se resuelve con un flujo
existente o un cambio de proceso. Decirlo con claridad es criterio, no pesimismo.

### Cómo priorizamos
- **NECESARIO:** sin esto el problema sigue vivo.
- **ÚTIL:** mejora el día a día y cuesta poco.
- **BONITO:** no cambia el resultado. Se ignora.
- **FUTURO:** "por si acaso". Se ignora.

### Antes de escribir código
Explicar el flujo en pocas líneas con un boceto de pantalla (mockup): quién lo usa,
qué toca, qué espera y qué pasa. Si no se puede explicar así de simple, primero se
entiende; no se escribe.
