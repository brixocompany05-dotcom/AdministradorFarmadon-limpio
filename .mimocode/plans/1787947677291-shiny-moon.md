# Plan: Cambiar Diálogo Anular Factura → Panel Inline

## Problema actual

El diálogo de Anular Factura es un `Dialog` flotante que cubre el 92% de la pantalla. En tablet horizontal, esto oculta la lista de facturas y rompe el contexto del usuario (cerebro-diseno §6: "antes de abrir una pantalla nueva, preguntar si el usuario necesita seguir viendo lo anterior").

## Solución propuesta

**Convertir el diálogo en un panel inline** que reemplaza el `DetalleFacturaLiquidacion` en el panel derecho (30%) de `PestanaCuentasPorPagar`. El usuario mantiene la lista de facturas visible a la izquierda mientras completa la anulación a la derecha.

### Layout actual vs propuesto

```
ACTUAL (diálogo flotante):                    PROPUESTO (panel inline):
┌────────────┬──────────────────────┐         ┌────────────┬──────────────────────┐
│ Lista 70%  │ Detalle 30%          │         │ Lista 70%  │ Anulación 30%        │
│ facturas   │ (se oculta detrás    │         │ facturas   │ (reemplaza detalle)  │
│            │  del diálogo)        │         │            │                      │
│            │                      │         │            │ Título + info        │
│  [DIÁLOGO FLOTANTE 92%]           │         │            │ 1. Motivo [▼]        │
│  ┌─────────────────────────────┐  │         │            │ 2. Tarjetas producto │
│  │ 60% formulario │ 40% resumen│  │         │            │ 3. Plata [▼]         │
│  │                │            │  │         │            │ ─────────────────    │
│  │                │            │  │         │            │ Resumen              │
│  │                │            │  │         │            │ [CANCELAR][ANULAR]   │
│  └─────────────────────────────┘  │         │            │                      │
└────────────┴──────────────────────┘         └────────────┴──────────────────────┘
```

### Cambio clave: Tabla → Tarjetas verticales por producto

La tabla de 5 columnas (PRODUCTO/LOTE, ENTRÓ, HOY, DEVUELVE, NO VUELVE) no cabe en el 30% del ancho. Se cambia a **tarjetas verticales** por producto:

```
┌─────────────────────────────────┐
│ Amoxicilina 500mg        Lote L-01│
│ Entró: 10  ·  Hoy en estante: 8  │
│ Devuelve: 8 (verde) · No vuelve: 2 (naranja)│
└─────────────────────────────────┘
┌─────────────────────────────────┐
│ Paracetamol 500mg        Lote L-03│
│ Entró: 5  ·  Hoy en estante: 5   │
│ Devuelve: 5 (verde) · No vuelve: 0│
└─────────────────────────────────┘
```

Cada tarjeta muestra:
- **Línea 1**: Nombre del producto + número de lote
- **Línea 2**: "Entró: X · Hoy en estante: Y"
- **Línea 3**: "Devuelve: X (verde) · No vuelve: Y (naranja)"
- Si el producto ya no existe o el lote no existe, nota en texto terciario

### Layout del formulario inline (vertical scroll)

1. **Cabecera**: "ANULAR FACTURA {número}" + proveedor/fecha/tipo
2. **Pregunta 1**: Motivo (dropdown `SelectorOpcion`)
3. **Pregunta 2**: "La app cuenta lo que hay en el estante" + tarjetas de productos
4. **Pregunta 3**: Plata (dropdown o banner de bloqueo)
5. **Resumen**: "Esto quedará escrito" — frase compacta
6. **Botones**: CANCELAR + ANULAR Y CERRAR (fijos al fondo del panel)

### Flujo de usuario

1. Usuario selecciona una factura en la lista (izquierda)
2. Panel derecho muestra `DetalleFacturaLiquidacion`
3. Usuario toca "ANULAR FACTURA" en el detalle
4. Panel derecho cambia a `FormularioAnularFactura` (inline)
5. Lista de facturas sigue visible a la izquierda (contexto mantenido)
6. Usuario completa las 3 preguntas + toca "ANULAR Y CERRAR"
7. Panel derecho vuelve a `DetalleFacturaLiquidacion` (factura ahora anulada)

### BackHandler

- Botón atrás cierra el formulario inline y vuelve al detalle
- Si está procesando, no hace nada

### Protecciones existentes (se mantienen)

- Solo dueño/admin puede anular facturas con plata pagada
- Spinner durante procesamiento
- Mensajes de error reales (R9)
- Transacción atómica en Firestore
